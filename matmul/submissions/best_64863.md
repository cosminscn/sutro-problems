## Method

Use four-row output tiles with nonuniform column widths 7+9, traversed by column
panel. Successive contraction passes reverse the column order. A operands are
staged just before use within each pass. In the second panel, preserve B operands
from their first cheap staged copy for reuse by later row tiles.

Three additional cheap recaptures shorten persistent lifetimes for B[0,13],
B[0,14], and B[0,8]. Each recapture copies the operand from an existing staged
value immediately before its last arithmetic use, then redirects later uses to
the new value. Optimize placement jointly across pairs of address-cost tiers,
including seeded cost-neutral moves. Each two-tier flow problem is exact; the
whole search is heuristic.

The final B[0,8] edit adds one read and initially raises cost from 64,872 to
64,873 with inherited homes. Two allocation rounds then reach 64,863. Unchanged
64,872 controls received the same rounds and seeds and did not improve. This
demonstrates a complete-program gain from the changed lifetime graph rather than
assuming separate optimizations' savings add together.

The arithmetic remains classical: 4,096 multiplications and 3,840 additions.
All entry placement, read-before-write reuse and final output reads obey the
existing scorer. This is 90 points below our earlier 64,953 candidate. No global
or full-trace allocation optimum is claimed; certificates for earlier traces do
not apply to this changed graph.

The complete replay starts from a semantic generator, without requiring a
downloaded competitor IR. The algorithm builds on the repository's column-major
staging and value-coloring work, earlier cheap-capture submissions, and the snake
traversal explored in Juraj Selep's [PR #50](https://github.com/cybertronai/sutro-problems/pull/50).
The retained 64,953 package documents that earlier seed's provenance.

## Verification

```sh
python3 matmul/submissions/best_64863.py
python3 -m pytest matmul/test_matmul.py matmul/test_record_64863.py
```

The standalone verifier uses only the standard library. It checks the exact IR
hash, official symbolic score, operation counts, category costs, and all 256
outputs with an independent noncommutative polynomial proof. The replay uses
pinned NumPy and OR-Tools dependencies and checks intermediate hashes before
comparing its final bytes with the submitted IR.

The research engine's C++ graph preparation increased experiment throughput;
the portable replay uses the equivalent reference Python preparation. Language
runtime is separate from the leaderboard's weighted-read cost.
