## Method

Start with the [64,448 program's literal raw generator](search_64448/reproduce.py).
Keep its arithmetic and copy graph: column panels [6,10], panel-specific row
groups [4,4,4,4] / [5,5,6], one-term/two-term contractions, rotated contraction
starts, column snakes, and 128 persistent B captures in columns 8–15.

Apply five legal changes to operation order before allocation. Each row below
uses zero-based positions in the list produced by the preceding row: remove
`operations[source:source+length]`, then insert that block at `destination` in
the shortened list.

| Step | Source | Destination | Length |
|---|---:|---:|---:|
| 1 | 7902 | 7905 | 2 |
| 2 | 7893 | 7991 | 1 |
| 3 | 1823 | 1825 | 1 |
| 4 | 226 | 222 | 4 |
| 5 | 1281 | 1287 | 1 |

The largest edit delays an existing partial-sum addition for C[14,13] by
98 positions. The complete order changes 117 positions; peak simultaneously
live values remains 606. Every source remains defined before use, and every
operation retains its original operands. No product, addition or copy is added
or removed. Every output consumes its 16 classical products exactly once.

Reallocate the complete trace using the weighted lifetime-chain initializer,
reparse the physical IR, then run two pair-allocation rounds with seed 0 and
ties disabled, followed by five rounds with seed 11 and ties enabled. The
portable implementation uses unchanged repository helpers and reference RNG.
These exact pair-tier optimizations form a heuristic overall allocator.

The combined change saves **17 points versus 64,448**: copy cost falls 13,
addition falls 12, multiplication is unchanged, and exit cost rises 8. These
are coupled full-program differences; the five edits are not five separately
measured additive gains.
