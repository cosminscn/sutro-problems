# Matrix Multiplication

**Author:** [@cosminscn](https://github.com/cosminscn) and Codex<br>
**Date:** 2026-09-04 (UTC)<br>
**Problem:** 16x16 matmul<br>
**Cost:** 64,475

## Method

Use a different row partition in each column panel. Columns **0–5** use row
groups **4+4+4+4** and one-term contraction chunks. Columns **6–15** use row
groups **5+5+6** and two-term chunks. Visit the narrow panel first, and reverse
column traversal after each contraction chunk within a tile.

Stage A at first use within a chunk and reuse it across the current column
panel. Stage B within each column and reuse it across the current row group.
For q2, consume the old C immediately: `(C + A[i,k]*B[k,j]) + A[i,k+1]*B[k+1,j]`.
Capture the first cheap staged value of each B input in columns 6–15 for the
later wide-panel row groups. There are 160 captures and 320 capture reloads.

The immediate 64,829 parent uses 5+5+6 rows in both panels. Changing only the
narrow panel to four-row groups reduces its macro output sizes from 30/30/36
to 24/24/24/24. The wide panel retains exactly the same ordered arithmetic
expressions and reduction trees. Its physical read prices can still change
because the complete program shares one address allocation.

Initialize addresses with the repository's weighted lifetime-chain allocator,
reparse the allocated physical IR to fix canonical value IDs, then run pair
allocation for two rounds with seed 0 and ties disabled, followed by five
rounds with seed 11 and cost-neutral moves enabled. The individual pair-tier
flows are exact; the full schedule/allocation procedure is heuristic.

The result is **354 points below 64,829**. Copy count increases by 96; copy cost
rises 663, while multiplication saves 198, addition 795, and exit 24. These are
measured costs of one complete witness. No optimal scheduling or allocation
claim is made. Fixed-trace lower bounds for prior submissions do not apply.

All 512 inputs are present at entry. Every operand read, including copy
sources and all 256 common-exit outputs, pays `ceil(sqrt(address))`. Physical
reuse obeys read-before-write semantics.

The verifier uses the unchanged official scorer and an independent exact
noncommutative proof for all 256 outputs, and checks the frozen IR hash,
instruction counts and category costs. The portable replay generates the
complete trace from literal loops, verifies four stage hashes and both
allocation-history hashes, and compares the final bytes with the submitted IR.
It requires no research workspace, competitor seed or machine-specific native
library. Pinned dependencies and unchanged repository-local helpers provide
the same reference allocation protocol used by earlier submissions.

The implementation builds on the repository's column-panel staging, persistent
cheap captures and value coloring. The immediate parent is the 64,829 mixed
chunk schedule; the earlier campaign's connection to Juraj Selep's PR #50 and
the attribution of the reused proof/allocation helpers remain documented in
the preceding reports. Discovery used native graph preparation; this package
replays with Python preparation and the same OR-Tools solver and reference RNG.
