## Method

Partition output rows into **5+5+6** and columns into **6+10**, visiting column
panels first. The six resulting tiles use contraction chunks of
**1,1,2,2,2,2**, in that order. Column traversal reverses between chunks.
A operands are staged at first use and shared across the current column panel;
B operands are staged for each column and shared across the current row group.

For a two-term chunk, update each existing C accumulator immediately with the
first product, then the second: `(C + A[i,k]*B[k,j]) + A[i,k+1]*B[k+1,j]`.
This differs from forming a separate two-product partial sum and adding it to C
later. The first two tiles use one-term chunks because their boundary and
lifetime costs favor that schedule.

For every B operand in columns 6–15, preserve its first staged value in a
persistent capture for the later row groups. This creates 160 captures. The
final generator has 1,440 copies, 4,096 multiplications, and 3,840 additions.

Initialize address placement with the repository's weighted lifetime-chain
allocator, reparse the allocated physical IR to canonicalize value IDs, then
run two pair-tier allocation rounds with seed 0 and ties disabled, followed by
five rounds with seed 11 and cost-neutral moves enabled. Each pair-tier flow
subproblem is exact; the complete schedule and allocation search are heuristic.

This program is **19 points below 64,863**. Its changed geometry and mixed
chunk schedule constitute a different instruction trace. No global or
fixed-trace allocation optimum is claimed, and lower-bound certificates for
earlier traces do not transfer to it.

| Instruction | Count | Paid reads | Read cost |
|---|---:|---:|---:|
| `mul` | 4,096 | 8,192 | 20,624 |
| `add` | 3,840 | 7,680 | 20,494 |
| `copy` | 1,440 | 1,440 | 19,225 |
| Output exit | — | 256 | 4,501 |
| **Total** | **9,376** | **17,568** | **64,844** |

All 512 inputs are present at entry. Every operand read, including copy sources
and the 256 outputs at the common exit, pays `ceil(sqrt(address))`. In-place
reuse obeys read-before-write semantics.

## Verification and reproduction

```sh
python3 matmul/submissions/best_64844.py
python3 -m pytest matmul/test_matmul.py matmul/test_record_64844.py
python3 -m pip install -r matmul/submissions/search_64844/requirements.txt
python3 matmul/submissions/search_64844/reproduce.py
```

The scorer wrapper needs only the standard library and repository files. It
checks the frozen IR hash, official symbolic score, all 256 outputs with an
independent noncommutative polynomial proof, operation counts, and category
costs. The full portable replay generates the trace from semantic loops, verifies
every stage hash, and compares its final bytes with the submitted IR. It does
not need a competitor seed, research workspace, native ABI, compiler, or network
access once its pinned dependencies are installed.

The implementation builds on the repository's column-panel staging, persistent
cheap captures, and value coloring, including the earlier work documented in
[the 64,863 submission](best_64863.md) and Juraj Selep's
[PR #50](https://github.com/cybertronai/sutro-problems/pull/50).
Research used native graph preparation to accelerate the same OR-Tools flow
solver; the included reproduction uses reference Python preparation and produces
identical bytes. Experiment runtime is separate from the weighted-read score.
